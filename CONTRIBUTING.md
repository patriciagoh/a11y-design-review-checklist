# Contributing to a11y-design-review-checklist

Thank you for considering a contribution. This document explains how to propose changes.

## What kind of changes are welcome

- New items for failure modes that are not yet covered.
- Sharper failure examples or test steps on existing items.
- New reference links on existing items.
- Bug fixes in `validate.js` or `scripts/generate-markdown.js`.
- New tags (proposed alongside the items that need them).

## What is NOT in scope

- WCAG Level AAA criteria.
- Items that aren't specific to the design-review UI pattern. Generic WCAG advice belongs in generic checklists.
- WCAG 3.0 / silver guidelines until the working group ships them.

## Editing items

`checklist.json` is the source of truth. **Never edit `checklist.md` directly** — it is generated by `scripts/generate-markdown.js` and CI will fail your PR if the two are out of sync.

```bash
# After editing checklist.json:
npm run validate
npm run generate-md
npm test
```

## Adding a new item vs. extending an existing one

**Add a new item** when the failure mode is meaningfully distinct: different test steps, different fail examples, distinct UI surface (e.g. pin vs. thread vs. workflow toolbar).

**Extend an existing item** when you're sharpening one of its arrays (more concrete fail examples, clearer test steps, additional reference link).

When in doubt, open an issue first.

## Item style

- **Title** is imperative or assertive, never "should" or "ideally": *"Annotation pins meet 4.5:1 against the artifact background"*, not *"Pins ideally have good contrast."*
- **Description** answers *why this matters in this UI pattern*. Don't restate the WCAG criterion.
- **how_to_test** steps are concrete and observable. Name UI elements: annotation pin, thread card, version diff overlay, workflow toolbar, presence avatar.
- **fail_examples** name colors, sizes, timings where applicable. Vague examples are not useful.
- Every item has at least one tag from the controlled vocabulary in the schema.

## ID convention

`<criterion>-<short-kebab-slug>` where `<criterion>` matches `wcag_criterion`. Example: `2.5.8-annotation-pin-target-size`. `validate.js` enforces the prefix match — if you change `wcag_criterion`, you must update the `id`.

IDs are stable across patch and minor versions. Renaming an `id` is a major-version change.

## Tag vocabulary

The tag vocabulary is locked in the schema. To add a new tag, your PR must:

1. Extend the `tags.items.enum` in `checklist.schema.json`.
2. Include at least one item that uses the new tag.
3. Note the change in the PR description (this constitutes a minor version bump).

## PR checklist

Before submitting:

- [ ] `npm run validate` passes.
- [ ] `npm test` passes.
- [ ] `npm run generate-md` was run and the regenerated `checklist.md` is committed.
- [ ] If `version` should bump (see Versioning in README), include the bump in your PR.
